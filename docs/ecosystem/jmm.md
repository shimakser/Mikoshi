# Java memory model (JMM), String pool

## Heap
Куча содержит все объекты, созданные в вашем приложении, независимо от того, какой поток создал объект. 
- Локальная переменная также может быть ссылкой на объект и хранится в стеке потоков, но сам объект хранится в куче. 
- Статические переменные класса также хранятся в куче. Является областью работы сборщика мусора.

## Stack
Стэк содержит информацию о том, какие методы вызвал поток и все локальные переменные для каждого выполняемого метода. 
- Работает по схеме LIFO (Последний-зашел-Первый-вышел).
- Поток может получить доступ только к своему стеку. Локальные переменные, невидимы для всех других потоков, кроме потока, который их создал. Даже если два потока выполняют один и тот же код, они всё равно будут создавать локальные переменные этого кода в своих собственных стеках. Таким образом, каждый поток имеет свою версию каждой локальной переменной. 
- Все примитивы полностью хранятся в стеке потоков и не видны другим потокам. Один поток может передать копию примитива другому потоку, но не может совместно её использовать.

Куча используется всеми частями приложения, в то время как стек используется только одним потоком исполнения программы.
Всякий раз, когда создается объект, он всегда хранится в куче, а в памяти стека содержится лишь ссылка на него. Память стека содержит только локальные переменные примитивных типов и ссылки на объекты в куче.

## Reordering Rules (Переупорядочивание)

Для оптимизации производительности компилятор (JIT) и сам процессор могут менять порядок инструкций. Главное правило здесь — as-if-serial semantics: переупорядочивание допускается только в том случае, если результат выполнения в рамках одного потока не изменится. Однако в многопоточной среде это может привести к катастрофе (например, инициализация объекта не завершена, а ссылка на него уже опубликована).

## Happens-Before

Это ключевая концепция JMM — отношение строгого частичного порядка между двумя действиями. 

Если действие A happens-before действия B, то результат действия A гарантированно видим действию B, и A выполняется до B.

**Основные правила happens-before:**
- **Program Order Rule** — Каждое действие в потоке happens-before каждого действия в том же потоке, идущего в коде позже.
- **Monitor Lock Rule** — Освобождение монитора (выход из synchronized) happens-before захвату того же монитора любым потоком.
- **Volatile Variable Rule** — Запись в volatile переменную happens-before любому последующему чтению этой же переменной.
- **Thread Start Rule** — Вызов Thread.start() happens-before любому действию в запущенном потоке.
- **Thread Termination Rule** — Любое действие в потоке happens-before обнаружению завершения этого потока (например, через Thread.join()).
- **Транзитивность** — Если A happens-before B, а B happens-before C, то A happens-before C.

## String pool

Пул строк — это специальная область в heap-памяти, где хранятся уникальные строковые литералы.
- Возможен благодаря неизменяемости строк в Java и реализации идеи интернирования строк;
- Помогает экономить память, но по этой же причине создание строки занимает больше времени;
- Когда для создания строки используются ", то сначала ищется строка в пуле с таким же значением, если находится, то просто возвращается ссылка, иначе создается новая строка в пуле, а затем возвращается ссылка на неё;
- При использовании оператора new создаётся новый объект String. Затем при помощи метода intern() эту строку можно поместить в пул или же получить из пула ссылку на другой объект String с таким же значением.

## Integer Cache Range

Для экономии памяти и ускорения работы JVM кэширует объекты оберток для небольших целочисленных значений.


- Диапазон по умолчанию: от -128 до 127 (включительно).
- _Как это работает:_ Кэш инициализируется при первом обращении к классу java.lang.Integer.IntegerCache. Если вы делаете Integer a = 100; (автоупаковка) или Integer.valueOf(100), JVM возвращает один и тот же объект из кэша. Если Integer a = 200; — создается новый объект.
- Вызов new Integer(100) всегда создает новый объект, игнорируя кэш. Именно поэтому конструкторы оберток задепрекейчены начиная с Java 9 (@Deprecated(since="9")).
- _Настройка:_ Верхнюю границу кэша можно изменить с помощью флага JVM: -XX:AutoBoxCacheMax=<size>. Нижняя граница всегда жестко зафиксирована на -128. Кэширование также применяется к Byte, Short, Long (всегда -128..127, не настраивается) и Character (0..127).

## Early vs Late Binding

Связывание (binding) — это процесс определения того, какой именно метод будет вызван.

### Early Binding (Раннее / Статическое связывание)

Происходит на этапе компиляции. Компилятор точно знает, какой метод нужно вызвать, так как переопределение (override) невозможно.


- _К чему применяется:_ private, static, final методы, а также перегруженные методы (overloading) и конструкторы.
- _Байт-код:_ Используются инструкции invokestatic (для статических) и invokespecial (для конструкторов, private методов и вызовов super).
- _Преимущества:_ Работает быстрее, отлично поддается инлайнингу (inlining) на уровне JIT-компилятора.

### Late Binding (Позднее / Динамическое связывание)

Происходит в runtime (во время выполнения). Используется для поддержки полиморфизма, когда тип переменной — это интерфейс или суперкласс, а реальный объект — подкласс.
 

- _К чему применяется:_ Все не-final и не-private методы экземпляра (overridden methods).
- _Как работает:_ JVM использует виртуальные таблицы (vtable) или интерфейсные таблицы (itable) для поиска нужного метода у конкретного класса в памяти.
- _Байт-код:_ Используются инструкции invokevirtual (вызов методов класса) и invokeinterface (вызов методов интерфейса). invokedynamic (появилась в Java 7) используется для лямбда-выражений.
