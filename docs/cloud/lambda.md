# Lambda

Это FaaS-платформа (Function as a Service).<br>
Код запускается по запросу, без управления серверами, без ручного масштабирования.

_Зачем используется:_
1. запуск кода по событиям (API Gateway, S3, SNS, SQS, DynamoDB Streams);
2. автоматическое масштабирование под нагрузку;
3. отсутствие управления серверами;
4. оплата только за время исполнения;
5. очень быстрый деплой и низкий операционный overhead.

_Типовые сценарии:_
* serverless REST API;
* обработка файлов/ивентов;
* ETL-пайплайны;
* cron-задачи;
* бэкенды для мобильных/IoT.

## Что такое "cold start" и как его минимизировать

Это задержка при первом запуске экземпляра Lambda-функции, когда AWS создаёт новую среду выполнения:
* создаёт контейнер;
* загружает runtime (Python/Java/Node…);
* инициализирует зависимости;
* выполняет блок init (outside handler).

_Причины cold start:_
* отсутствие уже "прогретого" контейнера;
* масштабирование "вверх";
* функция долго не вызывалась;
* использование тяжелых зависимостей (особенно JVM).

_Как минимизировать:_
1. Использовать Provisioned Concurrency<br>
    AWS заранее держит нужное количество прогретых экземпляров.
2. Минимизировать время init
   - меньше зависимостей;
   - лёгкие библиотеки;
   - не загружать большие объекты/коннекты на старте.
3. Использовать более быстрые языки загрузки<br>
   Node.js, Python → маленький cold start<br>
   Java, .NET → большой cold start (особенно с Spring)
4. Использовать GraalVM Native Image<br>
   В некоторых случаях сильно уменьшает cold start.
5. Избегать VPC, если не нужно<br>
    Подключение к VPC добавляет задержку на ENI.

## Можно ли вызвать одну Lambda из другой

Да.

Способы:
- Через AWS SDK (synchronous или asynchronous)<br>
    `LambdaClient.invoke()`<br>
- Через EventBridge
- Через SNS или SQS
- Через Step Functions

## Lambda Layers

Это способ вынести общие зависимости (библиотеки, вспомогательный код, бинарные файлы) в отдельный слой, чтобы:
* уменьшить размер самой функции;
* переиспользовать зависимости между несколькими функциями;
* обновлять один слой, а не 10 разных функций.

_Использовать когда:_
1. много функций используют одну и ту же библиотеку;
2. библиотеки большие (например pandas, numpy);
3. нужен общий runtime-слой;
4. нужно упростить деплой (меньше размера пакета).

_Не использовать когда:_
- зависимости часто меняются → увеличивается сложность версионирования.
