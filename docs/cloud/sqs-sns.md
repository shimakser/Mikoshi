# SQS, SNS

## SQS (Simple Queue Service): Рабочие очереди

Это сервис очередей сообщений. Он работает по модели Point-to-Point (точка-точка) и механизму **Pull** (опрос).

**Как это работает:** Продюсер отправляет сообщение в очередь. Сообщение надежно хранится там (по умолчанию до 4 дней, максимум 14). Консьюмер (микросервис-обработчик) должен сам прийти и сказать: «Дай мне работу» (Polling). Каждое сообщение обрабатывается только одним консьюмером.

**Ключевые концепции:**
1. **Visibility Timeout (Таймаут видимости)** — Это защита от потери данных. 
    Когда воркер A забирает сообщение из очереди, оно не удаляется сразу! Оно становится невидимым для воркера B на заданное время (например, 30 секунд). Если воркер A успешно обработал задачу, он обязан послать команду DeleteMessage. Если воркер A упал с ошибкой (или завис) и таймаут истек, сообщение снова становится видимым, и его заберет воркер B.
2. **Standard vs FIFO**:
    - _Standard_ — Гарантирует доставку как минимум один раз (At-least-once). Сообщения могут прийти не по порядку, а иногда (из-за распределенной природы серверов AWS) могут быть доставлены дубликаты. Ваш код консьюмера обязан быть идемпотентным. Бесконечная пропускная способность.
    - _FIFO (First-In-First-Out)_ — Строгий порядок и гарантия доставки ровно один раз (Exactly-once, с помощью дедупликации по ID). Минус — жесткий лимит на пропускную способность (обычно 3000 сообщений в секунду с батчингом).
3. _DLQ (Dead-Letter Queue)_ — Очередь недоставленных сообщений. 
   Если сообщение вызывает ошибку в коде (например, кривой JSON) и возвращается в очередь 5 раз подряд (настраиваемый параметр maxReceiveCount), SQS автоматически перекладывает его в DLQ.

## SNS (Simple Notification Service): Шина событий

SNS работает по паттерну **Pub/Sub** и механизму **Push**.

**Как это работает:** Продюсер публикует сообщение в канал связи, который называется Topic (Топик). К этому топику могут быть подключены десятки разных подписчиков (Subscribers). Как только сообщение попадает в топик, SNS автоматически и мгновенно рассылает (Push) копию этого сообщения всем подписчикам.

**Ключевые концепции:**
1. _Типы подписчиков_ — Подписчиками могут быть другие AWS-сервисы (Lambda-функции, SQS-очереди), HTTP/HTTPS эндпоинты ваших серверов, или даже email-адреса и SMS-номера конечных пользователей.
2. _Message Filtering (Фильтрация сообщений)_ — Мощнейшая фича. Если в топик падают все события о заказах (order_created, order_cancelled, order_shipped), а вашему сервису нотификаций нужны только order_shipped, вы можете настроить фильтр прямо на стороне SNS. SNS просто не будет отправлять лишние события вашему сервису, экономя ваши деньги на вычислениях.
3. _Отсутствие долговременного хранения_ — В отличие от SQS, SNS не хранит сообщения долго. Если SNS пытается отправить сообщение вашему HTTP-серверу, а он лежит (возвращает 503), SNS сделает несколько попыток (retries) по экспоненциальной задержке, а потом сообщение будет навсегда потеряно (если к подписке не привязана своя DLQ).
