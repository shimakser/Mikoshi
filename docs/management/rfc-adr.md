# RFC/ADR‑процессы

RFC → обсуждение → решение → ADR

---

## RFC

Request For Comments<br>

    RFC — это документ «давайте обсудим, как лучше сделать»

Когда нужен RFC:
* меняем архитектуру
* выбираем новую технологию
* вводим сложное правило
* решение влияет на много команд

_RFC = этап обсуждения._

---

## ADR

Architecture Decision Record<br>

    ADR — это документ «мы решили сделать вот так, и вот почему»

Это уже зафиксированное решение.

Зачем ADR:
* через 6–12 месяцев никто не помнит, почему так
* новый разработчик быстро понимает контекст
* не возвращаться к уже принятым решениям

_ADR = архитектурная память команды._
