# Deployment strategies

## Recreate (обычная перезагрузка)

Старая версия выключается → новая версия запускается.

_Минусы:_
- Даунтайм.
- Риск ошибок при миграциях.

_Когда применяют:_
- Внутренние сервисы без SLA по доступности.

---

## Rolling Update

Инстансы обновляются по очереди:
N старых → выключили один → подняли новый → так до конца.

_Плюсы:_
- Нет даунтайма.
- Работает во всех оркестраторах (Kubernetes, ASG и т.д.).

_Минусы:_
- Некоторое время работают две разные версии.
- Требует обратной совместимости (backward compatibility).

_Когда применять:_
- Микросервисы, публичные API, веб-приложения.

---

## Blue-Green

Есть две версии:
- Blue — текущая
- Green — новая

- Трафик переключается целиком на Green мгновенно.

_Плюсы:_
- Почти нулевой даунтайм.
- Легкий откат (просто переключить обратно).

_Минусы:_
- Нужно держать дубликат всей инфраструктуры.
- Дороже по ресурсам.

_Когда применять:_
- Критичные системы, где важен быстрый rollback.

---

## Canary Release

Часть трафика (например, 1-5%) направляется на новую версию.
Если всё нормально → увеличиваем процент → полностью переключаем.

_Плюсы:_
- Минимизирует риски.
- Изолирует ошибки на малом трафике.
- Откатывается быстро.

_Минусы:_
- Более сложная маршрутизация.
- Сложнее мониторить и сравнивать.

_Когда применять:_
- Сервисы с высокой нагрузкой, требующие плавных релизов.

---

## A/B Deployment

Разные группы пользователей получают разные версии одновременно.
Цель — сравнение поведения, конверсий, метрик.

_Плюсы:_
- Отлично для экспериментов.

_Минусы:_
- Нужна инфраструктура, которая умеет маршрутизацию по группам.

_Когда применять:_
- B2C-продукты, веб-сервисы, фичефлаги.

---

## Shadow Deployment (Mirror / Dark Launch)

Трафик копируется на новую версию, но ответы от неё игнорируются.
Новая версия работает “в тени”.

_Плюсы:_
- Тестирование на реальном трафике без влияния на пользователей.

_Минусы:_
- Дороже (дублирование нагрузки).
- Новая версия должна быть полностью идемпотентной.

_Когда применять:_
- Нагрузочное тестирование на реальных данных.
- Проверка производительности.

---

## Feature Flags / Toggle-based Deploy

Код деплоится заранее, но логика включается/выключается флагом.

_Плюсы:_
- Деплой ≠ релиз функциональности.
- Лёгкий rollback фичи.
- Гибкое включение для отдельных групп.

_Минусы:_
- Усложняет код.
- Нужна инфраструктура для хранения флагов.

_Когда применять:_
- Частые релизы.
- Постепенное включение функционала.

---

### Immutable Deployment

Старая версия не обновляется — просто создаются новые инстансы с новой версией.
Старые уничтожаются после переключения.

_Плюсы:_
- Нет "дрейфа конфигураций".
- Предсказуемость среды.

_Минусы:_
- Требуются автоматизированные пайплайны.
- Больше потребление ресурсов.

_Когда применять:_
- Kubernetes, EC2 ASG, облачные платформы.
