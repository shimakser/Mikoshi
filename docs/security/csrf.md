# CSRF

Cross-Site Request Forgery

CSRF (Подделка межсайтовых запросов) — это атака, при которой злоумышленник заставляет браузер жертвы выполнить нежелательное действие на доверенном сайте (где жертва уже авторизована). Это работает потому, что браузеры автоматически прикрепляют Cookies (включая сессионные) ко всем кросс-доменным запросам.

## Как Spring Security защищает от CSRF

Spring Security использует паттерн Synchronizer Token. При отдаче HTML-формы сервер генерирует уникальный случайный токен. При отправке мутирующих запросов (POST, PUT, DELETE) клиент обязан передать этот токен в теле формы или в заголовке X-CSRF-TOKEN. Атакующий не может прочитать этот токен с чужого домена из-за политики CORS.

## CSRF и Stateless JWT (Важный архитектурный нюанс)

Многие разработчики пишут `http.csrf().disable()` при настройке REST API. Это безопасно только в одном случае: если вы храните JWT на клиенте в памяти (или LocalStorage) и передаете его в заголовке Authorization.

- **Почему безопасно:** Потому что браузер не отправляет этот заголовок автоматически при кросс-доменных запросах (в отличие от кук). Нет автоматической отправки учетных данных — нет CSRF-уязвимости.
- **Когда отключать нельзя:** Если вы храните ваш JWT в HttpOnly Cookie (для защиты от XSS-атак), ваш REST API снова становится уязвим для CSRF, и вам необходимо настроить передачу CSRF-токена (например, через CookieCsrfTokenRepository).
